# Память о проекте ORVI Simulator

Описание сохранено по просьбе пользователя 25 сентября 2026 года после чтения исходников, README и конфигурации сборки. При изменениях проекта актуализировать сведения; при расхождениях опираться на текущий код.

## Назначение

ORVI Simulator — шуточная фоновая программа для Windows 10/11 и macOS, которая имитирует «простуду» компьютера. Это локальная настольная утилита без основного интерфейса, сервера и базы данных. Согласно описанию проекта, предназначена для собственного компьютера или запуска с согласия владельца.

## Устройство и файлы

- `orvi.py` — весь исходный код: настройки, эффекты, автозагрузка, горячая клавиша, защита от нескольких экземпляров и основной цикл.
- Стек: Python, `pywin32`, Win32 API через `ctypes`, `winreg`; красный оверлей создаётся через `tkinter`. MP3 воспроизводятся через Windows MCI (`winmm.dll`).
- `sounds/` — `sneeze.mp3`, `cough.mp3`, `blow_nose.mp3`. README указывает Pixabay как источник; лицензии отдельно не проверялись.
- `ORVISimulator.spec` — сборка PyInstaller в один исполняемый файл без консоли, со встроенной папкой звуков.
- `mac/orvi_mac.py` — macOS-версия: эффекты, файловая защита от второго экземпляра, пользовательский LaunchAgent и стоп-файл. `ORVISimulatorMac.spec` собирает `.app` universal2 без значка в Dock.
- `releases/ORVISimulator-macOS-universal2.zip` — локально собранное и проверенное на структуру macOS-приложение; подпись ad hoc, без нотарификации Apple. Windows-архив `releases/ORVISimulator-Windows-x64.zip` должен собираться workflow `.github/workflows/build-windows.yml` на Windows runner и добавляться в Git.
- Локально в `dist/` есть старая Windows x86-64 GUI-сборка около 10 МБ. Соответствие бинарного файла текущему исходнику не проверено, поэтому его не следует публиковать как актуальный.
- В старой истории Git папки `build/`, `dist/`, `__pycache__/` и `.idea/` отслеживались. Для новой публикации добавлен `.gitignore`; готовые архивы размещаются только в `releases/`, а промежуточные файлы сборки не публикуются.
- Отдельного манифеста зависимостей пока нет. Тесты находятся в `tests/`; Windows CI собирает текущий `.exe` на Windows runner.

## Фактическое поведение исходного кода

- Перед каждым основным действием программа ждёт случайные 3–7 секунд. Сами эффекты выполняются последовательно и добавляют время к циклу.
- С равной вероятностью выбирается один из трёх эффектов: чих со звуком и открытием браузера (`about:blank`), Диспетчера задач, экранной клавиатуры или Проводника; кашель со звуком и дрожанием подходящих видимых окон около 1,2 секунды с попыткой возврата на исходные позиции; сморкание со звуком и 4–9 нажатиями увеличения либо уменьшения системной громкости.
- После основного действия с вероятностью 18% показывается полупрозрачный красный оверлей («температура»), с заданной длительностью 2,5–4,5 секунды плюс небольшие задержки анимации.
- При обычном запуске код регистрирует видимое задание `ORVISimulator` в Планировщике заданий через COM (`Schedule.Service`). Триггер — вход текущего пользователя, тип входа — интерактивный токен, уровень прав — обычный. Это запускает эффекты в пользовательском сеансе без `SYSTEM`, без пароля и без записи `Run`. При запуске из исходника действие вызывает Python с путём к скрипту; у собранного файла — сам `.exe`. Старую запись `HKCU\...\Run` код удаляет при миграции.
- После успешной регистрации обеих горячих клавиш и низкоуровневого хука программа блокирует события мыши (движение, кнопки, прокрутку). Если регистрация не удалась, эффекты не запускаются. Клавиатура остаётся доступной.
- `Ctrl+Alt+Shift+M` снимает блокировку мыши и удаляет задание Планировщика, оставляя остальные эффекты работающими. Ручной повторный запуск снова включает автозагрузку и блокировку.
- `Ctrl+Alt+Shift+Q` завершает текущий процесс и снимает блокировку мыши; задание Планировщика остаётся. Можно также завершить процесс через Диспетчер задач.
- `ORVISimulator.exe --uninstall` (также `/uninstall`, `-u`) пытается удалить задание Планировщика и старую запись `Run`; не удаляет файлы и не завершает уже работающий экземпляр.
- Именованный Windows mutex ограничивает запуск одним экземпляром.
- В просмотренном Python-коде не обнаружены сбор данных, сетевые запросы, самораспространение или удаление пользовательских файлов; браузер открывается на `about:blank`.

## Известные расхождения и ограничения

- README и начальный docstring были обновлены после обнаружения прежних расхождений об автозагрузке и интервале.
- Комментарий к оверлею обещает отсутствие перехвата кликов/фокуса, но явная настройка пропуска кликов и запрета активации в коде не реализована; поведение требует проверки на Windows.
- Многие исключения подавляются без журналирования, поэтому неработающие эффекты могут оставаться незаметными.
- Windows-эффекты не проверены на Windows в этой среде. macOS-приложение собрано на Mac, но эффекты не запускались, чтобы не включать автозагрузку и не менять рабочий стол при проверке.
- Блокировка мыши через `WH_MOUSE_LL` требует проверки на Windows; Windows может отключить низкоуровневый хук при слишком долгой работе обработчика. Имеющийся в `dist/` `.exe` нужно пересобрать после изменения исходника.
- Планировщик запускает программу после входа пользователя, а не до него: обычная служба Windows работает в отдельном сеансе 0 и не может напрямую применять эффекты к рабочему столу пользователя. Вариант с Планировщиком требует проверки на Windows.

## Сборка

На Windows с Python и Tkinter установить `pyinstaller` и `pywin32`, затем выполнить `python -m PyInstaller ORVISimulator.spec`. В README также приведена эквивалентная команда сборки с `--onefile --noconsole --add-data "sounds;sounds"`.

На macOS с universal2 Python и Tkinter установить `pyinstaller==6.16.0`, затем выполнить `python3 -m PyInstaller ORVISimulatorMac.spec`. Готовый `.app` архивируется в `releases/`. Mac-версия при обычном запуске создаёт `~/Library/LaunchAgents/com.orvi.simulator.plist`, а `--uninstall` удаляет и выгружает агент. Старый стоп-файл очищается при старте.
