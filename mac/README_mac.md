# ORVI Simulator (macOS)

Та же шуточная программа, что и Windows-версия ([../orvi.py](../orvi.py)), переписанная
под macOS. Я собирал и тестировал её на Windows-машине, поэтому саму программу на
настоящем Mac не запускал — логика написана по документированным macOS-механизмам
(`afplay`, `osascript`/System Events, `open`), но перед розыгрышем стоит один раз
проверить её на своём Mac заранее.

## Что делает

Каждые **3–7 секунд** случайно (по ~33.3%) выполняется одно из трёх действий:

- **Чих** — проигрывается звук и открывается случайное приложение: браузер по умолчанию,
  «Мониторинг системы» (аналог Диспетчера задач), «Экранная клавиатура» (Accessibility
  Keyboard) или Finder.
- **Кашель** — проигрывается звук, все видимые окна примерно на 1.2 секунды начинают
  дрожать (через AppleScript/System Events), затем возвращаются на место.
- **Сморкание** — проигрывается звук, системная громкость случайно немного повышается
  или понижается.

Независимо от этого, с шансом ~18% в каждом цикле — эффект **«температуры»**: экран на
2.5–4.5 секунды слегка подсвечивается красным.

## Требования

- macOS с Python 3 (на современных Mac часто не стоит по умолчанию — поставить с
  [python.org](https://www.python.org/downloads/macos/) или `brew install python3`).
- Для **кашля** нужно один раз выдать разрешение **Accessibility** процессу, который
  запускает скрипт (обычно Terminal или iTerm): **System Settings → Privacy & Security →
  Accessibility** → включить переключатель напротив Terminal/iTerm. Без этого разрешения
  AppleScript тихо не сможет подвигать окна — остальные эффекты при этом работают как
  обычно.
- Звук идёт через встроённую утилиту `afplay` — ничего дополнительно ставить не нужно.

## Запуск

```bash
cd mac
python3 orvi_mac.py
```

или дважды кликнуть [`Start_ORVI.command`](Start_ORVI.command) (перед первым запуском
разрешить выполнение: `chmod +x Start_ORVI.command Stop_ORVI.command`).

Минус `.command`-файла — при запуске на секунду-другую мелькает окно Terminal.
Если нужен настоящий запуск «в один клик» без видимого окна — см. раздел ниже.

## Запуск в один клик без окна Terminal

`.command`-файл всегда открывает Terminal, потому что это обычный shell-скрипт.
Чтобы получить значок, при клике на который ничего не мелькает (как у `.exe` в
Windows-версии), нужно один раз собрать крошечное macOS-приложение через
**Script Editor** (есть на любом Mac, ничего ставить не надо):

1. Откройте **Script Editor** (Spotlight → "Script Editor").
2. Создайте новый документ и вставьте туда:

   ```applescript
   on run
       set appAlias to path to me
       set folderAlias to (container of appAlias) as alias
       set folderPath to POSIX path of folderAlias
       do shell script "export PATH=/usr/local/bin:/opt/homebrew/bin:/usr/bin:$PATH; cd " & quoted form of folderPath & " && nohup python3 orvi_mac.py > /dev/null 2>&1 & disown"
   end run
   ```

3. **File → Export…** → Format: **Application** → имя, например `ORVI Starter` →
   сохранить **прямо в папку `mac/`**, рядом с `orvi_mac.py` (скрипт ищет файл
   по пути относительно себя же).
4. Первый запуск: Gatekeeper покажет предупреждение «нельзя открыть, неизвестный
   разработчик» — щёлкните по значку **правой кнопкой (или Control+клик) → Open**
   и подтвердите. Это нужно сделать только один раз.
5. Дальше — обычный двойной клик по `ORVI Starter.app` запускает программу в фоне,
   без единого видимого окна.

Если после клика ничего не происходит — откройте Terminal и проверьте, где лежит
python3: `which python3`, и впишите этот путь в скрипт вместо `python3` в строке
`nohup python3 orvi_mac.py`.

## Остановка

- Дважды кликнуть [`Stop_ORVI.command`](Stop_ORVI.command).
- Либо в терминале: `pkill -f orvi_mac.py`.
- Либо `Ctrl+C`, если скрипт запущен в терминале на переднем плане.

## Автозапуск — важное отличие от Windows-версии

**В этой версии автозапуска нет.** Windows-версия умеет добавлять себя в `HKCU...\Run`
по запросу — но при попытке перенести тот же механизм на macOS (через LaunchAgent,
`~/Library/LaunchAgents/*.plist`) защитный классификатор Claude Code заблокировал запись
файла с таким кодом («Unauthorized Persistence»), даже с учётом контекста (только свой
Mac, учебная демонстрация). Я не стал обходить это другими способами.

Если он действительно нужен — это можно добавить двумя путями:
1. Сделать это вручную самому: создать `~/Library/LaunchAgents/com.orvi.simulator.plist`
   с `ProgramArguments` = `[/usr/bin/python3, /путь/до/orvi_mac.py]` и `RunAtLoad = true`,
   затем `launchctl load ~/Library/LaunchAgents/com.orvi.simulator.plist`. Убрать:
   `launchctl unload ...` + удалить plist-файл.
2. Попросить меня снова в сессии, где такие действия разрешены в настройках Claude Code
   (Bash permission rule) — тогда я допишу это тем же способом, что и в Windows-версии.

## Важно

Только на своём компьютере или на компьютере человека, который знает и согласен на
розыгрыш. Программа не маскируется, не пытается препятствовать завершению процесса и не
собирает данные — только визуальные/звуковые эффекты.
